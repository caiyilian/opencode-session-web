# 会话更新监控通知脚本 — 可行性分析

## 目标

编写一个独立于 Web 页面的后台脚本，监控 opencode 的所有对话，当某条对话有**新回复**时，通过微信推送通知。

## 可行性结论

**完全可行**。核心逻辑简单，依赖少，预计 100-150 行 Python 代码即可完成。

---

## 技术方案

### 1. 如何检测"有新回复"

opencode 的所有数据存在 SQLite 数据库 `~/.local/share/opencode/opencode.db` 中。

关键字段：

```sql
-- session 表：time_updated 在每次更新时自动变更
-- message 表：新增 AI 回复时写入新行
```

检测方式有两种：

**方案 A：轮询 message 表（推荐）**

```python
# 记录每个 session 最后已知的消息时间
last_seen = {}  # session_id -> last_time_created

# 每次轮询：
rows = cursor.execute("""
    SELECT session_id, MAX(time_created) as last_msg
    FROM message
    GROUP BY session_id
""").fetchall()

for r in rows:
    sid = r["session_id"]
    new_time = r["last_msg"]
    if sid in last_seen and new_time > last_seen[sid]:
        # 有新的消息 → 发通知
        notify(sid)
    last_seen[sid] = new_time
```

**方案 B：轮询 session 表的 time_updated**

```python
rows = cursor.execute("""
    SELECT id, title, directory, time_updated
    FROM session
""").fetchall()

for r in rows:
    if last_seen.get(r["id"]) and r["time_updated"] > last_seen[r["id"]]:
        notify(r["id"], r["title"], r["directory"])
    last_seen[r["id"]] = r["time_updated"]
```

方案 B 更简单，但不能区分"用户发了消息"和"AI 回复了"。但是方案 A 也不完美，因为 opencode 可能在用户发消息时创建新消息记录。

更精确的做法：**同时检查 `message` 表的新增行中 `role = 'assistant'`**。

### 2. 微信通知

通知需要发到微信，目前有以下可行渠道：

| 渠道 | 方式 | 成本 | 可靠性 |
|------|------|:----:|:------:|
| **企业微信机器人 Webhook** | HTTP POST 到 webhook URL | 免费 | ✅ 稳定 |
| **Server 酱 (sct.ftqq.com)** | HTTP GET/POST | 免费（有频率限制） | ✅ 稳定 |
| **PushPlus** | HTTP POST | 免费 | ✅ 稳定 |
| **ClawBot / 自定义微信机器人** | HTTP 调用 | 取决于具体实现 | ⚠️ 需要用户自行搭建 |
| **WeChat 个人号（itchat）** | 模拟登录 | 免费 | ❌ 容易被封 |

最推荐的方式是 **企业微信机器人 Webhook** 或 **Server 酱**，只需一个 HTTP 请求即可推送到微信。

> 如果你用的是 "clawbot"，它通常也提供 HTTP API 接口，配置方式类似。

通知内容示例：

```
📬 opencode 新回复

文件夹：E:/projects/my-project
对话：修复登录页面的 bug
模型：deepseek-chat
时间：2026-06-21 13:09
```

### 3. 脚本设计

```python
# monitor.py — 独立运行，不依赖 Web 项目
import sqlite3
import time
import json
import urllib.request

DB_PATH = "~/.local/share/opencode/opencode.db"
WEBHOOK_URL = "https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx"
POLL_INTERVAL = 5  # 秒

def send_notification(session_id, title, directory, model):
    msg = {
        "msgtype": "text",
        "text": {
            "content": f"📬 opencode 新回复\n\n文件夹：{directory}\n对话：{title}\n模型：{model}"
        }
    }
    req = urllib.request.Request(
        WEBHOOK_URL,
        data=json.dumps(msg).encode(),
        headers={"Content-Type": "application/json"},
    )
    urllib.request.urlopen(req)

def main():
    last_seen = {}  # session_id -> time_updated
    while True:
        conn = sqlite3.connect(DB_PATH)
        cursor = conn.cursor()
        rows = cursor.execute(
            "SELECT id, title, directory, model, time_updated FROM session"
        ).fetchall()
        conn.close()

        for r in rows:
            sid = r["id"]
            updated = r["time_updated"]
            if sid in last_seen and updated > last_seen[sid]:
                send_notification(sid, r["title"], r["directory"], r["model"])
            last_seen[sid] = updated

        time.sleep(POLL_INTERVAL)

if __name__ == "__main__":
    main()
```

### 4. 启动方式

```bash

```

## 注意事项

1. **轮询间隔**：5 秒一次对 SQLite 几乎没有压力，`session` 表一般不到 100 行
2. **首次运行**：第一次启动时所有 session 都会触发通知（因为 `last_seen` 为空）。需要加一个 `--no-initial` 参数跳过首次
3. **并发问题**：Python 的 sqlite3 模块在多进程同时写入时可能报 `database is locked`。可以用重试机制解决
4. **通知去重**：同一条会话在短时间内多次更新时，可以用 30 秒冷却期避免重复通知
