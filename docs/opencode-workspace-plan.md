# OpenCode Workspace：项目任务工作台与执行闭环

目标：把当前的会话浏览器升级为本地 OpenCode 工作台。用户打开 Web 后，可以围绕一个项目查看会话、任务、代码变更、运行命令和验证结果，并把 OpenCode 的执行过程沉淀成可追踪的工作记录。

## 产品边界

- 继续保留现有会话浏览、搜索、继续、新建、Fork、Undo、Delete、Compare、Provider 管理和实时同步能力。
- 新增 Workspace 视角，先以项目为核心聚合数据，再逐步承载任务、Git、命令执行和验收记录。
- 所有会触发本机命令的能力必须有明确的安全边界：白名单、工作目录约束、可见输出和失败状态。

## 阶段规划

### 阶段 1：项目工作台基础

- 后端提供项目聚合 API：会话数、消息数、token、成本、最近会话、常用模型和最近活跃时间。
- React 显示 Workspace 面板，当前选中会话所在项目成为工作台上下文。
- 保留按目录筛选和会话浏览行为。

验收：

- `/api/workspace/projects` 返回 schema 兼容的项目聚合数据。
- React 首屏能看到项目工作台摘要，并可从工作台切换项目目录。
- 后端 pytest、前端单测和 E2E 不回退。

### 阶段 2：任务模型和项目任务面板

- 增加本地任务存储，记录 title、description、project_path、status、linked_session_ids、created_at、updated_at。
- 提供任务 CRUD API。
- React 在 Workspace 面板内显示任务列表、状态筛选、任务详情和关联会话。

验收：

- 能在 Web 创建任务并绑定当前项目。
- 任务可以关联已有会话和新建会话。
- 刷新页面后任务状态和关联关系保持。

### 阶段 3：Git 变更面板

- 后端读取项目目录的 `git status --porcelain`、当前 branch、最近 commits 和文件 diff 摘要。
- React 显示当前项目的变更、分支、最近提交和风险提示。
- 会话/任务可记录当时的 Git snapshot。

验收：

- Git 项目显示 branch、dirty file count 和变更文件列表。
- 非 Git 项目显示清晰空状态。
- 路径被约束在项目目录内，不允许任意路径命令执行。

### 阶段 4：命令运行与验证配置

- 项目级配置常用命令：test、build、lint、dev server。
- 后端通过受控 runner 执行命令并流式输出。
- React 显示命令运行历史、实时日志、退出码和耗时。
- 当前基础切片已实现：JSON 白名单、非 shell argv 执行、项目目录内 cwd 约束、运行记录持久化、React 验证面板。下一步继续把输出从同步返回升级为实时流式输出。

验收：

- Web 可触发白名单命令并看到实时输出。
- 命令失败时保留错误日志和退出码。
- Flask 退出时清理正在运行的命令进程。

### 阶段 5：OpenCode 执行闭环

- 任务详情内可发起 OpenCode 会话、继续会话或 Fork 会话。
- OpenCode 完成后自动关联会话、Git snapshot 和可选验证命令结果。
- 提供“生成阶段说明/PR 描述/验收记录草稿”入口。

验收：

- 一个任务可以从描述、OpenCode 执行、代码变更、测试结果到验收记录形成闭环。
- 出错时能看到模型错误、命令错误和剩余动作。

### 阶段 6：安全、审计和最终验收

- 补齐命令白名单、危险命令确认、路径约束、操作日志和权限提示。
- 扩展 Playwright E2E 覆盖 Workspace、任务、Git 和命令执行主流程。
- 更新 README 和最终验收记录。

验收：

- 项目工作台、任务、Git、命令运行、OpenCode 会话和验收记录主流程可重复验证。
- 不破坏原有会话管理功能。
