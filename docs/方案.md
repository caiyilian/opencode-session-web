# OpenCode 会话 Web 管理器 — 可行性分析与方案设计

> 在浏览器中浏览、管理和继续 OpenCode 对话历史

---

## 1. 可行性结论

**完全可行。** OpenCode 使用 SQLite 存储所有会话数据，Python 的 `sqlite3` 可以直接读取。Web 前端可以用原生 HTML + CSS + JS 实现，不需要复杂框架。对于 Phase 2 的"继续对话"功能，可以通过 `opencode run --format json` CLI 子进程实现流式交互，不需要 Node.js SDK。

---

## 2. OpenCode 数据存储方式

### 2.1 数据库位置

OpenCode 将会话数据存储在本地 SQLite 数据库中：

| 系统 | 路径 |
|------|------|
| Linux | `~/.local/share/opencode/opencode.db` |
| macOS | `~/Library/Application Support/opencode/opencode.db` |
| Windows | `C:\Users\<用户名>\.local\share\opencode\opencode.db` |

### 2.2 核心表结构

**`session` 表** — 存储每次对话的元信息：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | text (PK) | 会话 ID，如 `ses_126a110e...` |
| `project_id` | text | 关联项目 ID |
| `directory` | text | **工作目录路径**（关键字段） |
| `title` | text | 会话标题 |
| `model` | text | 使用的模型 |
| `agent` | text | 使用的 agent |
| `time_created` | integer | 创建时间（Unix 毫秒） |
| `time_updated` | integer | 最后更新时间 |
| `cost` | real | 消耗金额 |
| `tokens_input` | integer | 输入 token 数 |
| `tokens_output` | integer | 输出 token 数 |
| `metadata` | text | JSON 元数据 |

**`message` 表** — 存储每条消息：

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | text (PK) | 消息 ID |
| `session_id` | text (FK) | 所属会话 |
| `time_created` | integer | 发送时间 |
| `data` | text | 消息全文（JSON 格式，含 role / content / parts 等） |

**`project` 表** — 项目信息：

| 字段 | 说明 |
|------|------|
| `id` | 项目 ID |
| `worktree` | Git worktree 路径 |
| `vcs` | 版本控制信息（JSON） |

### 2.3 当前数据量

当前本地数据库约 614 MB，会话数量较多，按目录分组后有几十个项目目录。数据库查询效率良好，加上索引后分页查询响应在毫秒级。

## 3. 关键挑战

### 挑战一：数据在本地，服务在云端

数据存储在本地 PC 上，而 Web 服务需要公网访问才能用手机查看。解决方案：通过 **Cloudflare Tunnel** 或 **frp** 将本地端口暴露到公网，不需要把数据库上传到云服务器。

### 挑战二：OpenCode SDK 是否需要实例

- 只读模式（Phase 1）：❌ 不需要，直接读 SQLite
- 交互模式（Phase 2）：✅ 需要，但可以用 `opencode run --format json` CLI 子进程替代 SDK

### 挑战三：手机端使用

通过 Cloudflare Tunnel 暴露到公网后，手机浏览器直接访问 HTTPS 地址。前端已做响应式适配。

### 4.6 关于"继续对话"的实现

Phase 2 采用 **opencode CLI 子进程方案**，而不是 `@opencode-ai/sdk`：

```
┌─ Flask 后端 ──────────────────────┐
│                                    │
│  POST /api/sessions/:id/resume     │
│       │                            │
│       ▼                            │
│  subprocess.Popen([                │
│    "opencode", "run",              │
│    "-s", session_id,               │
│    message,                        │
│    "--format", "json"              │
│  ])                                │
│       │                            │
│       ▼ (逐行读取 stdout)          │
│  {"type":"text","text":"正在..."}  │
│  {"type":"reasoning",...}          │
│  {"type":"step_finish",...}        │
│       │                            │
│       ▼ (通过 SSE 推送到前端)      │
│  event: text                       │
│  data: 正在...                     │
│                                    │
└────────────────────────────────────┘
```

`opencode run --format json` 输出的是按行分隔的 JSON 事件流，包含以下事件类型：

| 事件类型 | 说明 |
|---------|------|
| `step_start` | 步骤开始 |
| `text` | AI 回复文本 |
| `reasoning` | 思考过程 |
| `tool_use` | 调用工具 |
| `tool_result` | 工具返回结果 |
| `step_finish` | 步骤完成（含 Token 消耗） |

Flask 后端通过 SSE (Server-Sent Events) 将这些事件实时推送到前端。

#### 5.2.3 关键实现细节

**SSE 流式响应：**

```python
@app.route("/api/sessions/<session_id>/stream")
def api_session_stream(session_id):
    message = request.args.get("message", "")
    
    def generate():
        proc = subprocess.Popen(
            ["opencode", "run", "-s", session_id, message, "--format", "json"],
            stdout=subprocess.PIPE, stderr=subprocess.PIPE, text=True
        )
        for line in proc.stdout:
            try:
                event = json.loads(line.strip())
                if event["type"] == "text":
                    yield f"event: text\ndata: {event['part']['text']}\n\n"
                elif event["type"] == "reasoning":
                    yield f"event: thinking\ndata: {event['part']['text']}\n\n"
            except json.JSONDecodeError:
                pass
        
        # 获取最新的会话数据
        yield f"event: done\ndata: {json.dumps({'session_id': session_id})}\n\n"
    
    return Response(generate(), mimetype="text/event-stream")
```

## 6. 关于云服务器的角色

你的云服务器在这个方案中**不是必需的**。因为：

1. 数据在本地 PC 的 `opencode.db` 中
2. Web 服务跑在本地 PC 上
3. 手机通过 **Cloudflare Tunnel** 或 **frp** 直接访问本地服务

**推荐方案**：Web 服务在本地 PC 运行，通过 Cloudflare Tunnel 暴露到公网。

### 在 PC 上安装 cloudflared，一条命令

```bash
# Windows (choco)
choco install cloudflared

# macOS
brew install cloudflared

# Linux
wget -q https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64 -O cloudflared
chmod +x cloudflared
```

会生成一个 `https://xxx.trycloudflare.com` 的公开地址，手机打开即可访问：

```bash
cloudflared tunnel --url http://localhost:8765
```
