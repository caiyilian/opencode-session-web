fix: capture stderr errors from opencode CLI and forward as SSE events

When a model has usage limits (e.g. big-pickle), opencode run writes
the error to stderr and produces no stdout. Previously the SSE stream
hung forever with a spinner. Now:

- Stderr is read in a separate thread and collected
- If stdout produces no output and stderr has content, send stderr as error event
- Refactored shared logic into run_opencode_stream() helper
- Fixed Python 3.8 f-string backslash compatibility
